Webhooks let your application receive real-time notifications when events happen in Google — without polling the API. When a subscribed event occurs, Google sends an HTTP `POST` request to the URL you register, containing a JSON payload with the event details. This is the most efficient way to keep your systems in sync with changes to accounts, resources, and team membership.

<Warning>
  Always verify the webhook signature before processing any payload. Skipping verification exposes your endpoint to spoofed requests from malicious third parties.
</Warning>

## Supported Events

Subscribe to any combination of the following event types when registering a webhook:

| Category | Event | Description |
|----------|-------|-------------|
| Accounts | `account.created` | A new account was created |
| | `account.updated` | An account's details were changed |
| | `account.deleted` | An account was deleted |
| Resources | `resource.created` | A new resource was created |
| | `resource.updated` | A resource was updated |
| | `resource.deleted` | A resource was deleted |
| Members | `member.invited` | A user was invited to the organization |
| | `member.joined` | A user accepted an invitation and joined |
| | `member.removed` | A member was removed from the organization |
| Integrations | `integration.connected` | A third-party integration was connected |
| | `integration.disconnected` | An integration was disconnected |

## Webhook Payload Format

Every webhook delivery uses the same envelope format. The `type` field tells you which event occurred, and the `data` object contains the full state of the affected resource at the time of the event.

```json
{
  "id": "evt_01H8XYZ",
  "type": "resource.created",
  "created_at": "2024-01-15T10:30:00Z",
  "data": {
    "id": "res_01H8ABC",
    "name": "Q4 Marketing Plan",
    "type": "document",
    "workspace_id": "ws_01H9ABC"
  }
}
```

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Unique identifier for this event delivery, prefixed with `evt_` |
| `type` | string | The event type, e.g. `resource.created` |
| `created_at` | string | ISO 8601 timestamp of when the event was triggered |
| `data` | object | The full resource object associated with the event |

## Register a Webhook

`POST /v1/webhooks`

Register a new webhook endpoint to start receiving event notifications.

### Body Parameters

<ParamField body="url" type="string" required>
  The publicly accessible HTTPS URL where Google should deliver events. Must use `https://`.
</ParamField>

<ParamField body="events" type="array" required>
  An array of event type strings to subscribe to. Example: `["resource.created", "resource.updated"]`. Pass `["*"]` to subscribe to all events.
</ParamField>

<ParamField body="secret" type="string">
  A secret string used to sign webhook payloads with HMAC-SHA256. Store this securely — you'll use it to verify incoming requests. If omitted, Google generates one for you.
</ParamField>

<ParamField body="description" type="string">
  An optional human-readable label to help identify this webhook in the dashboard.
</ParamField>

### Request

```bash
curl -X POST https://api.google.com/v1/webhooks \
  -H "Authorization: Bearer ggl_live_xxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://yourapp.com/webhooks/google",
    "events": ["resource.created", "resource.updated", "account.created"],
    "secret": "your_webhook_secret",
    "description": "Production event listener"
  }'
```

### Response

```json
{
  "data": {
    "id": "wh_01H9GHI",
    "url": "https://yourapp.com/webhooks/google",
    "events": ["resource.created", "resource.updated", "account.created"],
    "description": "Production event listener",
    "status": "active",
    "created_at": "2024-04-01T09:00:00Z"
  }
}
```

## Verify Webhook Signatures

Google signs every webhook delivery using HMAC-SHA256 with your webhook secret. The signature is included in the `X-Google-Signature` request header. Verify it against the raw request body before processing any payload.

```javascript
const crypto = require('crypto');

function verifyWebhook(payload, signature, secret) {
  const hmac = crypto.createHmac('sha256', secret);
  const digest = hmac.update(payload).digest('hex');
  return crypto.timingSafeEqual(
    Buffer.from(digest),
    Buffer.from(signature)
  );
}
```

Use `crypto.timingSafeEqual` (or your language's equivalent) to prevent timing-based attacks. A standard string comparison leaks information about how many characters match, making it exploitable.

Here is an example of how to use this in an Express.js handler:

```javascript
app.post('/webhooks/google', express.raw({ type: 'application/json' }), (req, res) => {
  const signature = req.headers['x-google-signature'];
  const isValid = verifyWebhook(req.body, signature, process.env.WEBHOOK_SECRET);

  if (!isValid) {
    return res.status(401).send('Invalid signature');
  }

  const event = JSON.parse(req.body);
  // Handle event...
  res.status(200).send('OK');
});
```

## Best Practices

Follow these guidelines to build a reliable webhook consumer:

**Respond quickly.** Your endpoint must return a `2xx` response within **5 seconds**. If Google does not receive a `2xx` within that window, it marks the delivery as failed and retries with exponential backoff. Offload any slow processing to a background job and return `200 OK` immediately.

**Return `200 OK`.** Any `2xx` status code signals successful delivery. Returning a `4xx` or `5xx` triggers a retry.

**Handle events idempotently.** Google may deliver the same event more than once in rare cases (e.g., network timeouts before your `200` was received). Use the `id` field on each event payload to deduplicate — store processed event IDs and skip any you've already handled.

**Use HTTPS only.** Google will not deliver events to plain `http://` URLs. Ensure your endpoint has a valid TLS certificate.

**Monitor for failures.** Check the Webhooks section of your dashboard to view delivery logs and retry events that failed due to downtime on your end.
